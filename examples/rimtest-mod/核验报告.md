## 1. 这是什么、不是什么

**是**：在没有启动游戏的前提下，用「本机 1.7 的真实数据」对 mod 做 8 类机械检查——XML 能否解析、Def 名是否唯一、父 Def 是否真实存在、贴图路径是否落地、每个字段路径是否在 1.7 字段表里出现过、Patch 结构是否合法、XML 引用的 C# 类型是否真的在 DLL 里。

**不是**：不能替代运行时测试。它查不出「运行时行为错误」「平衡性」「补丁是否真生效」「贴图是否好看」。真正的验收在 [TESTING.md](TESTING.md) 第 3 节。

## 2. 怎么复现

```powershell
node docs/verify-testmod.mjs --mod "examples\rimtest-mod\RimTestMod" \
     --out "examples\rimtest-mod\核验报告.json"
```

可选参数：`--rimworld <游戏目录>`（默认 `E:\SteamLibrary\steamapps\common\RimWorld`）、`--library <模板库>`（默认 `library`）。有 error 时退出码 1，只有警告时退出码 0——适合直接挂进 CI。

## 4. 4 条警告：都是预期良性

| 警告 | 为什么不是错 |
|---|---|
| `productHasIngredientStuff` 不在字段表 | 该字段名确实存在于 `Assembly-CSharp.dll` 的元数据（UTF-8 名表偏移 12707852），但**原版 XML 0 处使用**（`costStuffCount` 类配方由 `RecipeDefGenerator` 在代码里生成），所以按原版统计出来的字段表天然缺它。本 mod 是手写配方，必须显式写这个字段，否则产物不继承输入材料。**这是字段表的盲区，不是 mod 的错误。** |
| `products/DM_Weapon_PlasmaDagger` 不在字段表 | 1.7 的 `products` 是字典写法：子元素名 = 产物 defName、值 = 数量。字段表无法预先枚举任意 defName。 |
| `products/DM_Weapon_IonRifle` 不在字段表 | 同上。 |
| `comps/li/shieldCapacity` 不在字段表 | 本 mod 自定义 comp（`CompProperties_TestShield`）的属性，字段表只收原版字段。 |

- **7 个父 Def 全部真实存在且是抽象 def**：`BaseMeleeWeapon_Sharp_Quality`（`Core/Defs/ThingDefs_Misc/Weapons/BaseWeapons.xml:179`）、`BaseBullet`（:98）、`BaseHumanMakeableGun`（:86）、`ApparelMakeableBase`（`Apparel_Various.xml:45`）、`ResourceBase`（`Items_Resource_Base.xml:4`）、`BenchBase`（`Buildings_Production.xml:125`）、`PlantBase`。
- **原版索引到的字面量**：音效 `Shot_ChargeRifle` / `Shot_Revolver` / `GunTail_Medium` / `Metal_Drop`、effecter `Smith`、工作类型 `Smithing` / `Gunsmithing` / `ChargedShot` / `ComplexClothing`、未完成物 `UnfinishedWeapon` / `UnfinishedGun`、房间角色 `Workshop`、ThingCategory `ResourcesRaw` / `ApparelMisc`、stat `GeneralLaborSpeed` / `StuffEffectMultiplierArmor` / `StuffPower_Armor_Sharp` … 全部在 1.7 原版 Data 里命中。
- **类名**：`Building_WorkTable`（原版 17 处用法）、`CompProperties_AffectedByFacilities`（25 处）、`PlaceWorker_ShowFacilitiesConnections` / `PlaceWorker_ReportWorkSpeedPenalties` / `PlaceWorker_PreventInteractionSpotOverlap`。
- **枚举**：`RimWorld.TechLevel` = `Undefined / Animal / Neolithic / Medieval / Industrial / Spacer / Ultra / Archotech`（反射 `Assembly-CSharp.dll` 得到）——注意**没有** `Ultratech`，Ultra 级科技就是 `Ultra`。

## 6. 核验器**没有**检查的东西（诚实清单）

1. 运行时行为（护盾是否吸收伤害、补丁是否真生效、配方是否出现在账单里、植物是否生长）——必须开游戏。
2. 贴图的**视觉**正确性（姿势、朝向、是否紫块或空白）——核验器只确认文件存在。
3. 平衡性与设计意图。
4. `0Harmony.dll` 与 net10.0 运行时的兼容性。
5. `legacyFolderName` 的实际取值（`Assembly-CSharp.dll` 里只读不写，无法静态确定），因此语言目录名只做到「136 个工坊 mod 的群体证据 + TESTING.md 的 L2 实验」。
6. `DamageResult` 是 class 还是 struct（所以补丁不声明 `__result`）。
7. 本 mod 与其它 mod 的兼容性（例如两个 mod 同时改 `Gun_Revolver`）。

## 7. 结论

交付副本在 8 类机械检查上全部通过；4 条警告全部有据可查、且其中 2 条本身是「1.7 字段表盲区」这一技能改进点。**下一步只剩运行时测试**：按 [TESTING.md](TESTING.md) 第 3 节逐项点，把不通过的现象贴回来。
