# 1.6 → 1.7 mod 迁移指南

> 本文件由三份实测报告提炼而成（证据均为**本机真实文件 + 命令 + 输出**，非网络资料）：
> `docs\差异-16到17.md`（对比 136 个已装 mod 中同时含 1.6/1.7 目录的样本）、`docs\样本-17版mod结构.md`（22 个含 1.7 目录 mod 的结构分析）、`docs\验证-csharp-1.7.md`（Assembly-CSharp.dll / UnityStubs.dll / coreclr.dll 静态核对）。
> 环境：游戏 1.7.4981 rev136；创意工坊 136 个 mod，其中 **22 个含 1.7 目录**、**50 个在 About.xml 里声明了 1.7**。

## 0. 一句话结论

**XML/Def 层几乎不用改**（7 组同名 XML 逐字节相同，没有任何 1.7 强制新字段）；
**要改的是「怎么把 mod 装进 1.7」**：声明版本、目录、DLL 目标框架、Harmony 依赖；**如果 mod 碰渲染或 Unity API，那要真改**。

## A 类：必须改（不改会加载失败或静默失灵）

| # | 改动 | 证据 / 说明 |
|---|---|---|
| A1 | **About.xml 的 `<supportedVersions>` 加 `<li>1.7</li>`** | 22/22 含 1.7 目录的 mod 全部声明；格式**未变**，仍是 `X.Y` 纯主次版本（官方 ModUpdating.txt L253-254 "Entries must be in X.Y format"）。整段缺失/为空是硬错误："`<supportedVersions>` in mod About.xml must specify at least one version."；格式错也会报 "Unable to parse version string on mod" |
| A2 | **DLL 用 net10.0 重编** | csproj `net472` → `net10.0`（16/22 样本如此），引用包 `Krafs.Rimworld.Ref` 1.6.4488-beta → 1.7.4977-alpha.1。证据：`...\294100\3216091476\1.7\Source\mod.csproj`。引用改成游戏根目录的 `Assembly-CSharp.dll`（1.7.97xx）+ `UnityStubs.dll`，**不要再引用 `UnityEngine.*.dll`** |
| A3 | **Harmony 升到 3.x 且外置** | 游戏安装目录递归搜 `*Harmony*` = **0 命中**。Harmony 现在是独立 mod **2009463077**（1.7 子目录里 `0Harmony.dll` = 3.0.0.0-rc.3 / net10.0，`HarmonyMod.dll` = 3.0.1.0）。样本 csproj 的 `Lib.Harmony` 也从 2.3.1.1 → 3.0.0-rc.2。About.xml 里用 `<modDependencies>` 声明 `brrainz.harmony` |
| A4 | **碰 Unity 渲染的代码要重写** | 1.6 时代用的 `RenderTexture.GetTemporary` / `Graphics.Blit` / `Texture2D.ReadPixels` / `GL.PushMatrix+LoadPixelMatrix+Graphics.DrawTexture+PopMatrix` 在 1.7 样本里**被整体删除**，改为纯 CPU 实现（`Color[]` + `GetPixelBilinear` + `SetPixels` + 手写 alpha 合成）。相关 stub 清单见 `02-模板/07-CSharp/06-UnityStubs兼容层与失效API.md` |
| A5 | **建 `1.7\` 目录**（多版本共存时） | 引擎会自动探测：`Verse.ModContentPack::InitLoadFolders` 会 `Path.Combine(RootDir, VersionControl.CurrentVersionStringWithoutBuild)`，而该串就是 `"1.7"`。12/22 个样本写了 LoadFolders.xml（其中 11 个写了 `<v1.7>`），另 10/22 个**没写也能加载** |
| A6 | **预编译的 Unity AssetBundle Shader 失效** | 1.7 改成 `ShaderDef` + `.glsl`（见 C1）。旧 Shader 资产不再被渲染管线消费 |

## B 类：可选但建议

| # | 改动 | 收益 |
|---|---|---|
| B1 | 随 DLL 输出 `<Mod>.deps.json` | 4 个样本都带，`runtimeTarget` = `.NETCoreApp,Version=v10.0`；换 CLR 后依赖解析更稳 |
| B2 | 打包 `Assets.zip`（现代替散装 Textures/Sounds） | 游戏本体自己也用（`Assets.zip` 358,892,126 字节）；样本内是 `Textures\**\*.png.dds` + `Sounds\**\*.ogg`，**不含 Defs**；官方提示 "Leave this unticked if you need compatibility with RimWorld 1.6 or earlier" |
| B3 | 统一 CRLF + UTF-8 BOM | 样本 mod 的实际做法 |
| B4 | 巨型 Patch 拆文件 + 用 `<insertTag>` | 便于维护、减少一个补丁失败拖垮整段 |
| B5 | 主界面按钮改用 `MainButtonDef` | 1.7 的新 Def 类型 |
| B6 | `IfModActive` 里写**真实 packageId** | LoadFolders 条件加载写错包名会静默不生效 |
| B7 | 删掉 HugsLib 等不再编译的依赖 | 减少加载期失败面 |
| B8 | 清理 `obj` / `.vs` / `.pdb` | 有 4 个样本 mod 是**空壳**（1.7 目录内容与 1.6 逐文件 SHA256 全同、甚至把 `Source/obj/.vs` 一起复制），别照抄这种结构 |

## C 类：1.7 新增能力（1.6 目录里完全没有）

| # | 能力 | 关键点 |
|---|---|---|
| C1 | **ShaderDef + `.glsl` 着色器** | XML 在 `Defs\ShaderDefs\`（官方样例 `Data\Core\Defs\ShaderDefs\Shaders.Map.xml`），GLSL 在 `Shaders\`。字段：`shaderProgram` / `vertexShaderFileName` / `fragmentShaderFileName` / `blendMode` / `useTexture` / `transparent` / `depthTest` / `depthWrite` / `cullMode` / `renderQueue`。GLSL 是 `#version 450`，`set=0/binding=0` 的 ViewProj + `push_constant modelMatrix`；还可写注释元数据 `// @vertex Position required`、`// @color`、`// @default`，以及 `#ifdef INSTANCED`。样本：`2917732219\1.7\Defs\ShaderDefs\MuzzleFlash.xml`、`3769804600\1.7\Defs\ShaderDefs\MineSight.xml` |
| C2 | **ShaderTypeDef** | `shaderPath` + `uiShaderPath`，官方样例 `Data\Core\Defs\Misc\ShaderTypeDefs\ShaderTypes.xml` |
| C3 | **Assets.zip 资源包** | 每个 load folder 一个（实测 `1662119905\1.7\Assets.zip`、`3220120457\1.7\Assets.zip`、`3264193512\Common\Assets.zip`）；引擎文案："has no load folder with textures or sounds, nothing to bake" |
| C4 | **MainButtonDef** | 主界面按钮，不用再靠 Harmony 注入 |
| C5 | **LoadFolders 条件加载 `IfModActive`** | `<li IfModActive="包名">子目录</li>`，还支持 `IfModActiveAll` / `IfModNotActive`（样本 839005762 用到） |

## D 类：**不需要**改的（这些负面结论同样重要，能防过度设计）

| # | 结论 | 证据 |
|---|---|---|
| D1 | **Defs 层没有 1.7 强制新字段** | 7 组同时含 1.6/1.7 目录、同名 XML 用 `Compare-Object` 比对，**内容完全一致**；1.7 目录的新增几乎只有「重编译 DLL + 少量新文件」 |
| D2 | `supportedVersions` 格式**没变**，仍是 `<li>1.7</li>` | 136/136 个 mod 都是传统 `<li>` 列表；正则 `1\.7[^,\s]` 全库 **0 命中** |
| D3 | **不强制要求 LoadFolders.xml** | 10/22 个含 1.7 目录的 mod 根目录根本没有该文件，照样加载。要用自定义共享目录（如 `Common\`）时才必须显式声明 `<li>Common</li>` |
| D4 | **Patch 机制没变** | 位置仍在 load folder 的 `Patches\` 下（1.7 专属即 `<mod>\1.7\Patches\**\*.xml`，可多层子目录），根元素 `<Patch>`，操作用 `<Operation Class="PatchOperationXxx">`，`<success>Normal\|Always\|Invert</success>`；可用 Sequence/Remove/Add/Replace/Conditional(nomatch/match)/Insert/AttributeSet，也可用 mod 自己 DLL 里的 PatchOperation 子类（样本 2888380373 的 `WVC_WorkModes.PatchOperation_Settings`） |
| D5 | 目标框架**变了但不硬性** | 1.7 侧 16/22 是 net10.0，但仍有 net472 / net4.8 / net8.0 / 原样不动的样本能加载（靠 `AssemblyNameRedirects` 等宽松开关）。**新写请用 net10.0** |
| D6 | **没有官方 1.7 迁移文档** | 游戏里 `ModUpdating.txt` 仅 404 行、唯一版本小节是 "1.0 -> 1.1"，且无 1.6/1.7/Waylith/shader 字样；`Readme.txt` 仍是旧的 `---_Data` 说明。**二者都不能作为 1.7 依据** |

## E 类：C# 侧细则（来自静态核对，运行期行为待验证）

- **入口类型全部还在**（Assembly-CSharp.dll 实测）：`Verse.Mod`(6 methods，构造签名不变)、`ModContentPack`(37)、`ModAssemblyHandler`(3)、`ModSettings`(5)、`DefOf`/`DefOfHelper`、`DefModExtension`(3)、`ThingComp`(82)、`CompProperties`(8)、`HediffComp`(33)。
- **`HarmonyLib` 在 Assembly-CSharp 里 0 个类型**——实现在 Harmony mod 的 `0Harmony.dll` 里；但官方**预期并消费** Harmony：`Verse.ProfilerUI.Dialog_ProfilerAssemblies::HarmonyPatchLines` 会反射调 `GetAllPatchedMethods`/`GetPatchInfo` 展示补丁列表，`ProfilerPrefs::Load` 还把 `0Harmony`/`MonoMod.*`/`Mono.Cecil*` 交给 `ProfilerInstrumentation.ExcludedAssemblies`。
- **补丁白名单**：`RimWorld.runtimeconfig.json` 有 `WaylithClr.JitPatchableAssemblies="Assembly-CSharp"`；coreclr.dll 里能找到 `EEConfig::JitPatchableAssemblies` 与 `JIT_Patchpoint*`。**风险点（推测）**：0Harmony 3.0 走自带 MonoMod 原生 detour，并有一条依赖 `clrjit/ICorJitInfo` 版本探测的路径，而 WaylithClr 是自研 CLR（10.0.13-waylithclr.dev），该路径可能失配——**只能实跑验证**。
- **UnityStubs 是真兼容层**（935 类型 / 7471 方法），不是空占位；「未实现」= 调 `UnityStubs.Internal.StubWarner::LogStub` 记一条警告后返回默认值，**不抛异常**（所以旧 mod 更可能**静默失灵**而不是崩溃）。全部 stub 只有 **257 个方法（88 个类型）**。
- **典型 stub**：`Input.GetAxis`、`Input.GetTouch`、`Time.timeScale` 赋值（且 `get_timeScale` 硬编码返回 1）、`Material.SetTexture`、`Object.hideFlags`、`Graphics.DrawTexture`/`ExecuteCommandBuffer`、`Resources.GetBuiltinResource`、`Mesh.Optimize`/`SetIndices`、`ScreenCapture.CaptureScreenshot`、`Unity.Profiling.Profiler`/`ProfilerRecorder`（改用 `Waylith.Profiling.*`）、`CommandBuffer`(30)、`ComputeShader`(12)、`CullingGroup`(12)、`Camera`(6) 等。
- **程序集加载规则**：`ModAssemblyHandler::ReloadAll` 对 `Assemblies\` 逐个 `Assembly.LoadFrom`，随后 `AssemblyIsUsable` 调 `assembly.GetTypes()`——**任何类型解析失败，整个 DLL 被拒**并打印 `Loader exceptions:`。所以**依赖的第三方 DLL 必须一起放进 `Assemblies\`**（实测 14/20 个样本 DLL 引用了 `0Harmony` 却不打包，靠依赖 Harmony mod）。
- **反射找 Unity 类型**时程序集名要写 `UnityStubs`（`UnityEngine.CoreModule`/`IMGUIModule` 等已不存在；有样本 mod 因仍引用它们而停留在 .NET Framework 4.8 + Assembly-CSharp 1.6.9676，属侥幸可加载）。

## F 类：原版数据里的坑（写 mod 时别被原版「带坏」）

| # | 现象 | 位置 |
|---|---|---|
| F1 | **小写 `<jobDef>` 根标签**共 6 处 | `Biotech\Defs\JobDefs\Jobs_Learning.xml`:16/22/28/34/40（Radiotalking、Floordrawing、Workwatching、Lessontaking、Lessongiving）+ `Core\Defs\JobDefs\Jobs_Misc.xml`:467（TriggerObject）。另有 60 多处小写 `jobDef` 只是其它 Def 的子元素引用，**不是**根标签 |
| F2 | **大写 `<BackStoryDef Abstract="True">`** 当父定义，子定义全写 `<BackstoryDef ParentName="Solid">` | `Core\Defs\BackstoryDefs\Solid\Solid_Rare.xml`:4（大写）vs :10/21/44/57/74/84/110（小写） |
| F3 | 上面两条说明 **1.7 的 Def 类型名匹配很可能不区分大小写**——否则约 800 个 `ParentName="Solid"` 的背景故事会全部报错（**推测，未实跑验证**）。**自己写 mod 一律用正确大小写** | 由必要性推证 |
| F4 | **`BiomeDef` 没有 `rocks` / `plantWildnessByLayer`**（`rockNoise`/`rockChunkChance`/`layers` 也全无） | BiomeDef 288 条路径不含；全本体 `rocks` 元素 **0 次**。现存岩石相关只有 ThingDef 的 `extraRockTypes`/`forceRockTypes` 与 `hasBedrock` |

| F8 | 存疑项：`analyzer.xml`（`3769804600` 根目录孤例）用途未证实；`TileMutatorDef` 在 22 个样本中 0 使用，版本归属未证实 | — |

## G 类：怎么自测（加载后看 `Player.log` 的这些字面量）

| 日志文案 | 含义 |
|---|---|
| `Loader exceptions:` | 你的 DLL 被整体拒载（多半是依赖 DLL 没放进 `Assemblies\`） |
| `ModLoadFolderDefinesUnsupportedGameVersion` / 相关 keyed 文案（`Data\Core\Languages\English\Keyed\Menus_Main.xml` L153-160） | LoadFolders 里声明了 1.7 目录但 About.xml 没写 1.7 |
| `Unable to parse version string on mod` | `supportedVersions` 格式不对（必须是 `X.Y`） |
| `<supportedVersions> in mod About.xml must specify at least one version.` | 完全没写版本 |
| `JIT version does not match expected JIT version!` / `Error while setting up the ICorJitInfo wrapper` | Harmony/MonoMod 与自研 CLR 的兼容告警（可能伴随补丁不生效） |
| `has no load folder with textures or sounds, nothing to bake` | Assets.zip/贴图烘焙相关提示 |
