# RimWorld 1.6 → 1.7 版本差异分析报告

- 分析对象：`<创意工坊目录>` 下 136 个创意工坊 mod 中「同时含 1.6 与 1.7 两个子文件夹」的 22 个
- 游戏版本：`<游戏安装目录>\Version.txt` = `1.7.4981 rev136`
> 路径占位符：`<游戏安装目录>` = 含 `Assembly-CSharp.dll` 的 RimWorld 根目录；`<创意工坊目录>` = `<Steam 库>\steamapps\workshop\content\294100`；`<Steam 库>` = Steam 库根目录。
- 结论标注约定：所有结论后附「文件路径 + 命令 + 真实输出」。凡未取得直接证据、仅由间接证据推出的判断，一律以 **推测：** 开头显式标出。

## 〇、取证方法与命令清单

PowerShell 7（FullLanguage）执行；每次调用为独立进程。关键注意点：`Get-Content -Encoding Byte` 在 PS7 会报错 `Byte is not a supported encoding name`，读字节必须用 `[System.IO.File]::ReadAllBytes()`。

| 目的 | 实际执行的命令 |
|---|---|
| 筛样本 | `Get-ChildItem -Path $root -Directory &#124; ForEach-Object { $d16 = Test-Path (Join-Path $_.FullName '1.6'); $d17 = Test-Path (Join-Path $_.FullName '1.7'); if($d16 -and $d17){ $_.Name } }` |
| 文件清单差异 | `$rel = { param($b) Get-ChildItem -Path $b -Recurse -File &#124; ForEach-Object { $_.FullName.Substring($b.Length+1) } }; Compare-Object -ReferenceObject (& $rel $p16) -DifferenceObject (& $rel $p17)` |
| 同名文件内容差异 | `Get-FileHash -Algorithm SHA256 <path>` 逐文件比对；文本文件另用 `Compare-Object (Get-Content $p16) (Get-Content $p17)` 逐行比对 |
| DLL 目标框架 | `$b=[System.IO.File]::ReadAllBytes($p); $s=[System.Text.Encoding]::Latin1.GetString($b); [regex]::Matches($s,'\.NET(CoreApp&#124;Framework&#124;Standard),Version=v[0-9.]+') &#124; ForEach-Object { $_.Value } &#124; Sort-Object -Unique` |
| DLL 程序集名/版本 | `[System.Reflection.AssemblyName]::GetAssemblyName($p)`；`[System.Diagnostics.FileVersionInfo]::GetVersionInfo($p).FileVersion` |
| deps.json | `Get-Content -Raw` 读取 + JSON 解析 |
| Assets.zip 内容 | `$z=[System.IO.Compression.ZipFile]::OpenRead($p); $z.Entries &#124; ForEach-Object { $_.FullName + ' ' + $_.Length }; $z.Dispose()` |
| 行尾统计 | `$b=[System.IO.File]::ReadAllBytes($p); $lf=0;$crlf=0; for($i=0;$i -lt $b.Length;$i++){ if($b[$i] -eq 10){ if($i -gt 0 -and $b[$i-1] -eq 13){$crlf++} else {$lf++} } }` |

## 四、存疑项

1. **1.7 是否要求 `supportedVersions` 新格式？——样本中未出现任何新格式。**
   22/22 个样本（以及全库 136 个 mod）的 `About\About.xml` 一律是传统写法 `<supportedVersions><li>1.6</li><li>1.7</li></supportedVersions>`（2113372560 甚至列了 `<li>1.1</li>…<li>1.7</li>`）。官方 `ModUpdating.txt` 与游戏语言文件中都没有其它格式的说明。
   **推测：** 1.7 未改变 `supportedVersions` 的书写格式，仍是 `<li>` 列表。

2. **是否强制要求 `LoadFolders.xml`？——不要求。**
   10/22 个样本根目录根本没有 `LoadFolders.xml`（1446523594、1508341791、1662119905、2113372560、2423311270、3216091476、3327029362、3513846773、3524116050、872762753），仍能提供 1.7 内容；`ModUpdating.txt` L206-213 明确写了「未定义则回退到上一版本或可用目录」。
   **推测：** 对「根目录 + 与版本号同名子目录」这种默认约定，`LoadFolders.xml` 是可选优化，而非必需。

3. **DLL 目标框架是否变化？——官方阵营变了，但运行时对旧框架有兼容层，「必须重编」不能算硬性禁止。**
   - 游戏本体：`net10.0`（`RimWorld.runtimeconfig.json`）+ WaylithClr 兼容开关全开。
   - 16/22 样本的 1.7 DLL 为 `.NETCoreApp,Version=v10.0`；`Krafs.Rimworld.Ref` 官方 mod 参照包 1.7 版为 `1.7.4977-alpha.1`。
   - **反例（说明旧框架未被硬性拒绝）**：`...\2113372560\1.7\Assemblies\TradeHelper.dll` 与 `...\2423311270\1.7\Assemblies\DestroyItem.dll` 两侧 TFM 分别都是 `v4.7.2` / `v4.8`；`2990606008` 与 `3524116050` 的 1.7 目录更是 1.6 的逐字节副本，内含 net472/net4.8 的 DLL。
   - **推测：** `WaylithClr.LaxAssemblyBinding`/`LaxAssemblyNameRedirects`/`AssemblyNameRedirects` 等开关使 net472/net4.8（乃至 net8.0）程序集仍可被加载；但「能加载」≠「能正确工作」，涉及渲染、反射、类型布局的代码风险很高。**推荐做法仍是重编为 net10.0。**

4. **`2917732219` 的 1.7 侧 `0Harmony.dll` 为 `.NETCoreApp,Version=v8.0`（net8.0），版本号却仍是 `2.3.3.0`**，与 1.6 侧版本号相同但 hash 不同。
   **推测：** 作者只把同一版 Harmony 用 net8.0 目标重编了一遍；net8.0 目标同样能被 1.7 运行时加载。

5. **`2888380373` 的 `LoadFolders.xml` 条件疑似写错。**
   该 mod `<v1.6>` 段用 `<li IfModActive="ludeon.rimworld.odyssey">1.6/Odyssey</li>`，而 `<v1.7>` 段改成 `<li IfModActive="brrainz.harmony">1.7/Odyssey</li>`。但游戏官方 `Data\Odyssey\About\About.xml` 实测 packageId 仍为 `Ludeon.RimWorld.Odyssey`。
   → **推测：** 这是作者笔误（把兼容条件从 Odyssey DLC 误改成 Harmony）。
